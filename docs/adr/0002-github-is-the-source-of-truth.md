# GitHub 是任务状态的权威来源，本地日志只用于追溯

任务、规格、评审、合并状态都记在 GitHub 的 issue、标签、PR 和 review 上。本地另有一份只追加的事件日志，记录每次运行的开始、结果、转交和决定，只回答"这一轮为什么跑"，不用来决定下一步做什么。调度器每次都从 GitHub 重新读取状态。

原因：开发者和别的工具也会直接改 GitHub 上的状态，把本地日志当权威会产生两份不一致的状态。调度器无状态后，崩溃或换一台机器都能直接继续。

## Considered Options

- 本地数据库为主，同步到 GitHub：能做复杂查询，但两边容易不一致，且要写同步逻辑。
- 只用 GitHub，不记日志：简单，但想知道某次运行的来龙去脉要翻多处评论。

## Consequences

- 每次调度都要读 GitHub，受 API 速率限制，轮询间隔不能太短。
- 日志丢失不影响任务继续，只影响追溯。
- 标签集合就是状态机，改标签含义要改文档和调度器。
